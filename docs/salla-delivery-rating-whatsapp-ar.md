# طلب تقييم واتساب بعد توصيل طلب سلة

الإصدار: `1.9.0`

## السلوك

1. يستقبل النظام حدث سلة الموقّع `order.status.updated`.
2. يقرأ حالة الطلب الفعلية، ولا يبدأ المسار إلا عندما يكون رمز الحالة `delivered` (تم التوصيل). حالة `completed` وحدها لا تكفي.
3. يحفظ سجل تقييم دائمًا وينشئ رسالة واحدة فقط لكل طلب، حتى لو أعادت سلة الحدث.
4. ينتظر افتراضيًا ساعتين بعد وقت التوصيل ثم يرسل قالب واتساب يطلب الرد برقم من 1 إلى 5.
5. قبل الإرسال يتحقق من:
   - وجود موافقة واتساب صريحة للعميل.
   - أن الميزة ما زالت مفعلة.
   - بوابات الإرسال العامة مثل `OUTBOUND_MODE` و`OFFICIAL_LAUNCH_APPROVED`.
6. تقييم 4 أو 5 يُحفظ ويُغلق الطلب برسالة شكر.
7. تقييم 1 إلى 3 ينشئ فورًا مهمة CRM عالية الأولوية، ثم يطلب من العميل كتابة سبب التقييم ويضيف الملاحظة إلى المهمة.

## الإعداد

```env
SALLA_DELIVERY_REVIEW_ENABLED=true
SALLA_DELIVERED_STATUS_SLUGS=delivered
SALLA_DELIVERY_REVIEW_DELAY_MINUTES=120
SALLA_DELIVERY_REVIEW_EXPIRY_MINUTES=10080
SALLA_DELIVERY_REVIEW_SESSION_MINUTES=10080
WHATSAPP_CLOUD_TEMPLATE_DELIVERY_REVIEW_REQUEST=
```

لا يحتاج هذا الإصدار صلاحية سلة جديدة؛ يعتمد على صلاحية الطلبات وحدث `order.status.updated` الموجودين في التكامل الحالي.

## قالب Meta

أنشئ قالبًا عربيًا معتمدًا يحتوي متغيرين في جسم الرسالة بهذا الترتيب:

1. اسم العميل.
2. رقم الطلب.

النص المقترح:

```text
مرحبًا {{1}} 👋
تم توصيل طلبك رقم {{2}}.
يهمنا رأيك في تجربتك معنا. قيّمها من 1 إلى 5 بالرد على هذه الرسالة.
```

بعد اعتماد القالب، ضع اسمه الفعلي في:

```env
WHATSAPP_CLOUD_TEMPLATE_DELIVERY_REVIEW_REQUEST=approved_template_name
```

## المراقبة

يستطيع الحساب المسجل قراءة سجلات التقييم من:

```text
GET /api/integrations/salla/delivery-reviews
```

الحالات الأساسية:

- `queued`: الرسالة مجدولة.
- `sent`: أُرسل القالب وبدأ انتظار التقييم.
- `submitted`: وصل تقييم 4 أو 5.
- `feedback_pending`: وصل تقييم من 1 إلى 3 وأنشئت متابعة عاجلة.
- `escalated`: وصلت ملاحظة العميل وحُفظت داخل مهمة CRM.
- `salla_delivery_review_consent_missing`: لا توجد موافقة واتساب صريحة؛ لم تُرسل الرسالة.
- `invalid_phone`: رقم العميل غير صالح للإرسال.

## التحقق قبل الإطلاق

```powershell
npm run doctor:prod
npm run test:unit
npm run test:schema
npm run build
```

نفّذ طلب اختبار مصرحًا به، غيّر حالته في سلة إلى `delivered`، وتحقق من:

1. ظهور سجل واحد في واجهة المراقبة.
2. إرسال قالب واحد فقط بعد مدة الانتظار.
3. حفظ تقييم 5 دون مهمة CRM.
4. إنشاء مهمة عالية الأولوية لتقييم 2 وتحديثها بعد ملاحظة العميل.

## الإيقاف السريع

```env
SALLA_DELIVERY_REVIEW_ENABLED=false
```

هذا يمنع إرسال طلبات تقييم جديدة ويحجب أي وظيفة معلقة عند محاولة تنفيذها، مع إبقاء السجلات السابقة للمتابعة.
