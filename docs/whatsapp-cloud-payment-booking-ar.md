# تشغيل واتساب كلاود للدفع والحجز الذاتي

الإصدار: `1.7.0`
آخر تحديث: 2026-07-27

## النتيجة التي ينفذها النظام

عندما يرسل العميل إلى رقم الشركة في واتساب:

- `السلام عليكم`: تظهر قائمة دفع أو حجز.
- `دفع`: يبحث النظام عن أحدث فاتورة صادرة وغير مدفوعة مرتبطة برقم العميل، وينشئ لها مطالبة واحدة في Tap ويرسل رابط الدفع.
- `حجز`: يتعرف على العميل والتركيبات المسجلة. العميل الجديد يُطلب منه الاسم والعنوان والخدمة.
- يعرض النظام خمسة مواعيد متاحة فقط، بعد احتساب ساعات العمل، الإجازة الأسبوعية، الحد اليومي لكل فني، وتعارض نفس الفني في نفس الساعة.
- بعد الاختيار، ينشئ حجزًا مؤكدًا في CRM ويُرسله إلى FieldTech، مع منع تكرار نفس الحجز.
- صفحة عودة الدفع العامة تتحقق من Tap، تحدّث الفاتورة، ولا تعرض اسم العميل أو رقم هاتفه.

التدفق يعمل حاليًا مع `SQLite` فقط، وهو مزود بيانات الاستضافة الحالية. إذا تغيّر مزود البيانات، يفشل الدفع والحجز الذاتي بأمان بدل إنشاء سجلات غير ذرية.

## حالة الربط التي فُحصت في 2026-07-27

- تطبيق Meta الموجود: `Golden Pro Cloud API`.
- رقم واتساب ظاهر في WhatsApp Manager كمتصل، وجودته مرتفعة.
- بيانات رقم Cloud والتوكن موجودة في بيئة الخادم، لكن المزود الحالي ما زال `web`.
- توكن تحقق Webhook وتوقيع Meta غير مضبوطين.
- مفتاح Tap السري غير مضبوط.
- تطبيق Meta غير منشور، وينقصه رمز تطبيق `1024×1024`؛ لذلك لا يُعتمد الإطلاق العام قبل إكمال أهلية التطبيق وتجربة رقم حقيقي مسموح.

هذه النقاط تعني أن الكود جاهز للاختبار، لكن الربط الحي مع العملاء لم يكتمل بعد.

## إعداد الخادم

أدخل القيم الحساسة مباشرة داخل `.env.production` على الخادم، ولا ترسلها في محادثة أو تضعها في Git:

```dotenv
DATA_PROVIDER=sqlite
WHATSAPP_PROVIDER=cloud_api
WHATSAPP_CLOUD_API_VERSION=v23.0
WHATSAPP_CLOUD_PHONE_NUMBER_ID=...
WHATSAPP_CLOUD_API_TOKEN=...
WHATSAPP_WEBHOOK_VERIFY_TOKEN=...
WHATSAPP_APP_SECRET=...

TAP_SECRET_KEY=...
TAP_BASE_URL=https://api.tap.company/v2

APP_URL=https://crm.breexe-pro.com
VITE_PUBLIC_CONTACT_PHONE=966...

WHATSAPP_COMMERCE_ENABLED=true
WHATSAPP_COMMERCE_SESSION_MINUTES=30
WHATSAPP_BOOKING_SLOT_TIMES=09:00,11:00,14:00,16:00
WHATSAPP_BOOKING_LOOKAHEAD_DAYS=10
WHATSAPP_BOOKING_MIN_LEAD_HOURS=4
WHATSAPP_BOOKING_CLOSED_WEEKDAYS=5
```

يبقى الإرسال محصورًا أثناء الاختبار:

```dotenv
OUTBOUND_MODE=allowlist
OUTBOUND_TEST_PHONE_ALLOWLIST=966...
OFFICIAL_LAUNCH_APPROVED=false
```

`WHATSAPP_APP_SECRET` هو سر تطبيق Meta، وليس توكن Cloud API. إذا كان Webhook يمر عبر وسيط موثوق لا يستطيع تمرير توقيع Meta، يمكن استخدام `WHATSAPP_WEBHOOK_SECRET` كبديل مشترك، لكن الربط المباشر مع Meta يجب أن يستخدم توقيع التطبيق.

## إعداد Meta

داخل تطبيق Meta > WhatsApp > Configuration:

1. ضع Callback URL:

   `https://crm.breexe-pro.com/webhooks/whatsapp`

2. ضع نفس قيمة `WHATSAPP_WEBHOOK_VERIFY_TOKEN`.
3. اشترك في حقل `messages`.
4. احفظ الإعداد وتأكد أن Meta نجح في تحدي التحقق.
5. أضف رمز التطبيق المطلوب وأكمل متطلبات نشر التطبيق قبل توسيع الاستخدام خارج أرقام الاختبار.

لا تحفظ App Secret أو Access Token في لقطة شاشة أو تذكرة دعم.

## إعداد Tap

1. أدخل Secret API Key الخاص بالبيئة المطلوبة مباشرة على الخادم.
2. النظام ينشئ Webhook لكل مطالبة على:

   `https://crm.breexe-pro.com/api/payments/webhook`

3. رابط عودة العميل هو:

   `https://crm.breexe-pro.com/pay/return`

4. لا تعتبر بوابة الدفع جاهزة للإنتاج قبل تجربة: إنشاء الرابط، إتمام الدفع، استلام Webhook، تحول الفاتورة إلى مدفوعة، ثم تجربة استرداد مضبوط من لوحة Tap.

## اختبار القبول قبل الإطلاق

بعد نشر الفرع وإعادة تشغيل الخدمة:

```powershell
npm run doctor:prod
```

يجب ألا يظهر فشل خاص بـ Cloud API أو توقيع Webhook أو Tap.

نفّذ الاختبار من رقم واحد موجود في قائمة السماح:

1. أرسل `السلام عليكم` وتأكد أن القائمة وصلت عبر WhatsApp Cloud.
2. أنشئ فاتورة اختبار صادرة لهذا الرقم، ثم أرسل `دفع`.
3. افتح الرابط وأكمل عملية Tap التجريبية.
4. تأكد أن الفاتورة أصبحت `paid` وأن إعادة كلمة `دفع` لا تنشئ مطالبة مكررة.
5. أرسل `حجز`، اختر خدمة وموعدًا، وتأكد أن الحجز ظهر مرة واحدة في CRM وFieldTech.
6. جرّب اختيار نفس الفترة من عميل آخر بعد امتلاء قدرة الفني، وتأكد أنها لا تُعرض أو يُعاد عرض بديل.

لا تغيّر إلى:

```dotenv
OUTBOUND_MODE=production
OFFICIAL_LAUNCH_APPROVED=true
```

إلا بعد نجاح الدفع والحجز من البداية إلى النهاية ومراجعة الرسائل.

## الإيقاف والتراجع

لإيقاف الدفع والحجز الذاتي فورًا دون فصل قناة واتساب كلها:

```dotenv
WHATSAPP_COMMERCE_ENABLED=false
```

ثم أعد تشغيل الخدمة. تبقى رسائل واتساب الأساسية ومسار الأقسام متاحة. ولإيقاف أي إرسال حقيقي أثناء التشخيص:

```dotenv
OUTBOUND_MODE=dry_run
OFFICIAL_LAUNCH_APPROVED=false
```

لا تحذف جلسة Cloud أو مفاتيح Tap كخطوة تراجع أولى؛ احفظها مشفرة ودوّر أي سر ظهر خارج مكانه الآمن.
